## ЛР 1 · Первая программа: типы, ввод-вывод, ветвления

### Базовое задание: секунды → ЧЧ:ММ:СС

**Условие.** Дана длительность в секундах. Выведите её в формате `ЧЧ:ММ:СС`, где минуты и секунды — двузначные числа с ведущим нулём, а часы — не менее двух цифр. Часы могут быть больше 24: это длительность, а не время суток.

**Входные данные.** Одно целое число S (0 ≤ S ≤ 10¹⁵).

**Выходные данные.** Одна строка в формате `ЧЧ:ММ:СС`. Если ввод не является неотрицательным целым числом, программа выводит сообщение в `stderr` и завершается с кодом 1.

**Примеры.**

| Ввод | Вывод |
|---|---|
| `0` | `00:00:00` |
| `3661` | `01:01:01` |
| `100000` | `27:46:40` |
| `-5` | сообщение об ошибке, код возврата 1 |

### Основное задание: тарификатор доставки

**Условие.** Служба доставки рассчитывает стоимость по правилам:

1. Базовая ставка зависит от зоны: зона 1 — 200 ₽, зона 2 — 350 ₽, зона 3 — 500 ₽.
2. За каждый килограмм сверх 5 кг добавляется 25 ₽.
3. С 22:00 до 6:00 действует ночная надбавка 20 % к стоимости, полученной по пунктам 1–2.
4. При сумме заказа от 3000 ₽ доставка бесплатна.

Напишите программу, которая по параметрам заказа вычисляет стоимость доставки. Если какое-то правило допускает несколько толкований, уточните его у преподавателя до начала работы — так же, как разработчик уточняет требования у заказчика.

**Входные данные.** Четыре числа через пробел: номер зоны (целое), вес посылки в килограммах (вещественное), час оформления заказа (целое, 0–23), сумма заказа в рублях (вещественное).

**Выходные данные.** Строка `Стоимость доставки: N руб`, где N — целое число рублей; для бесплатной доставки — `Стоимость доставки: 0 руб (бесплатно)`. При некорректных данных (не числа, зона не от 1 до 3, вес не положителен, час вне диапазона 0–23, отрицательная сумма) — понятное сообщение в `stderr` и код возврата 1.

**Требования.** Ставки и пороги оформлены именованными константами. В `README.md` приложена таблица «входные данные → ожидаемый результат», в которой проверено каждое правило и каждая граница (ровно 5 кг, ровно 22:00, ровно 6:00, ровно 3000 ₽).

**Примеры.**

| Ввод | Вывод |
|---|---|
| `2 7 12 0` | `Стоимость доставки: 400 руб` |
| `3 10 22 500` | `Стоимость доставки: 750 руб` |
| `1 1 23 3000` | `Стоимость доставки: 0 руб (бесплатно)` |
| `4 1 12 100` | сообщение об ошибке, код возврата 1 |

### Дополнительное задание: квадратное уравнение

**Условие.** Решите уравнение ax² + bx + c = 0 с вещественными коэффициентами, корректно обработав все вырожденные случаи. Вещественные числа сравнивайте с нулём с допуском ε = 10⁻⁹.

**Входные данные.** Три вещественных числа a, b, c.

**Выходные данные.** Ровно одна из строк:

| Случай | Вывод |
|---|---|
| a = 0, b = 0, c = 0 | `Любое x является решением` |
| a = 0, b = 0, c ≠ 0 | `Решений нет` |
| a = 0, b ≠ 0 | `Линейное уравнение, x = …` |
| D < 0 | `Действительных корней нет` |
| D = 0 | `Один корень: x = …` |
| D > 0 | `Два корня: x1 = …, x2 = …`, где x1 = (−b − √D) / 2a, x2 = (−b + √D) / 2a |

Значение `-0` выводиться не должно. При нечисловом вводе — сообщение в `stderr` и код возврата 1.

**Примеры.**

| Ввод | Вывод |
|---|---|
| `1 -3 2` | `Два корня: x1 = 1, x2 = 2` |
| `-1 3 -2` | `Два корня: x1 = 2, x2 = 1` |
| `1 2 1` | `Один корень: x = -1` |
| `0 2 0` | `Линейное уравнение, x = 0` |
| `0 0 5` | `Решений нет` |

## ЛР 2 · Циклы, функции и отладчик

### Базовое задание: НОД и НОК

**Условие.** Напишите функции `long long gcd(long long a, long long b)` и `long long lcm(long long a, long long b)` — наибольший общий делитель (алгоритмом Евклида) и наименьшее общее кратное. Результаты всегда неотрицательны; по определению НОД(0, 0) = 0, а НОК любого числа с нулём равен 0. Программа читает два числа и печатает оба результата.

**Входные данные.** Два целых числа a и b (|a|, |b| ≤ 10¹⁸). Гарантируется, что НОК помещается в `long long`; произведение a · b может не помещаться.

**Выходные данные.** Строка `НОД = g, НОК = l`. При нечисловом вводе — сообщение в `stderr` и код возврата 1.

**Требования.** Функция `run_tests()` содержит не менее 6 проверок `assert`, включая нули, отрицательные числа и пару чисел с переполняющимся произведением. `main` только читает и печатает.

**Примеры.**

| Ввод | Вывод |
|---|---|
| `12 18` | `НОД = 6, НОК = 36` |
| `0 7` | `НОД = 7, НОК = 0` |
| `-4 6` | `НОД = 2, НОК = 12` |
| `6000000000 4000000000` | `НОД = 2000000000, НОК = 12000000000` |

### Основное задание: алгоритм Луна

**Условие.** Платёжные системы проверяют номер карты алгоритмом Луна, чтобы отсечь опечатки до запроса в банк. Цифры номера просматриваются справа налево; каждая вторая цифра, начиная со второй справа, удваивается, и если результат больше 9, из него вычитается 9. Номер валиден, если сумма всех полученных цифр делится на 10.

Напишите функции `bool luhn_valid(long long number)` и `int check_digit(long long prefix)`. Вторая возвращает цифру, которую нужно дописать к `prefix`, чтобы номер стал валидным. Если введённый номер не валиден, программа подсказывает, какой должна быть его последняя цифра.

**Входные данные.** Номер карты — положительное целое число без пробелов (до 18 цифр).

**Выходные данные.** `Номер валиден` или `Номер не валиден; правильная последняя цифра: d`. Если ввод не является положительным числом — сообщение в `stderr` и код возврата 1.

**Требования.** Тесты на `assert` для обеих функций, включая контрольные номера из примеров.

**Примеры.**

| Ввод | Вывод |
|---|---|
| `4111111111111111` | `Номер валиден` |
| `5555555555554444` | `Номер валиден` |
| `4111111111111112` | `Номер не валиден; правильная последняя цифра: 1` |
| `79927398710` | `Номер не валиден; правильная последняя цифра: 3` |

### Дополнительное задание: быстрое возведение в степень по модулю

**Условие.** Вычислите aⁿ mod m двумя способами: наивно (n умножений) и быстрым возведением в степень за O(log n), опираясь на то, что aⁿ = (a²)ⁿ/² для чётного n и aⁿ = a · aⁿ⁻¹ для нечётного. Сравните время работы обоих способов при n = 10⁹.

**Входные данные.** Четыре целых числа: режим (1 — наивно, 2 — быстро), a, n, m (0 ≤ a, n ≤ 10¹⁸; 1 ≤ m ≤ 2³²).

**Выходные данные.** Строка `a^n mod m = r`. При некорректном вводе — сообщение в `stderr` и код возврата 1.

**Требования.** Тесты сверяют быстрый способ с наивным на всех a < 20, n < 50 и проверяют малую теорему Ферма: a^(p−1) mod p = 1 для простого p = 10⁹ + 7. Замеры — в сборке `-O2`.

**Примеры.**

| Ввод | Вывод |
|---|---|
| `2 2 10 1000` | `2^10 mod 1000 = 24` |
| `2 3 1000000000 1000000007` | `3^1000000000 mod 1000000007 = 235939645` |

## ЛР 4 · Структуры, сортировки и модульные тесты

### Базовое задание: рейтинг с общими местами

**Условие.** По результатам контрольной составьте рейтинг: участники упорядочиваются по убыванию балла, при равных баллах — по фамилии в алфавитном порядке. Участники с одинаковым баллом делят места: если трое набрали одинаковый балл и до них было два человека, все трое занимают места `3–5`, а следующий участник — место 6.

**Входные данные.** До конца ввода — строки вида `фамилия группа балл` (фамилия без пробелов, группа и балл — целые числа).

**Выходные данные.** Для каждого участника строка: место, фамилия, группа и балл, разделённые табуляцией. Место — одно число или диапазон через тире. Если строка не соответствует формату — сообщение в `stderr` с номером записи и код возврата 1.

**Требования.** Участник описывается структурой `struct Student`; сортировка — `std::sort` с компаратором-лямбдой.

Ввод:

### Основное задание: три сортировки, тесты и замеры

**Условие.** Реализуйте три сортировки с сигнатурой `void f(std::vector<int>& a)`:

1. `selection_sort` — сортировка выбором;
2. `insertion_sort` — сортировка вставками;

Проверьте их тестами и измерьте время работы.

**Требования к тестам (doctest).** Для каждой сортировки — граничные случаи (пустой массив, один элемент, уже отсортированный, обратный, все элементы равны, повторы) и стресс-тест: не менее 1000 случайных массивов, результат сравнивается с `std::sort`. При падении тест печатает входные данные. Тесты проходят под `-fsanitize=address,undefined`.

**Требования к замерам.** Программа измеряет время каждой сортировки и `std::sort` для n = 10³, 3·10³, 10⁴, 3·10⁴, 10⁵ на трёх видах данных: случайные, отсортированные, отсортированные в обратном порядке. Каждый алгоритм получает собственную копию одних и тех же данных; время генерации данных в замер не входит. Сборка — с `-O2`.

**Выходные данные.** Таблица времени работы в миллисекундах: размер, алгоритм, вид данных, время.

## ЛР 5 · Рекурсия, «разделяй и властвуй» и перебор

### Базовое задание: сортировка слиянием

**Условие.** Реализуйте сортировку слиянием `void merge_sort(std::vector<int>& a)`: массив делится пополам, половины сортируются рекурсивно и сливаются. Сортировка должна быть устойчивой и работать за O(n log n) на любых данных; вспомогательная память — один буфер размера n на всю сортировку.

**Требования.** Тесты и стресс-тест из ЛР 4 проходят для новой функции. Сортировка добавлена в программу замеров; в `README.md` — сравнение с сортировками из ЛР 4 и `std::sort` при n = 10⁵.

### Основное задание: быстрая сортировка со случайным опорным

**Условие.** Реализуйте быструю сортировку `void quick_sort(std::vector<int>& a)` с разбиением Ломуто и случайным выбором опорного элемента. Измерьте время её работы при n = 10⁵ на трёх видах данных: случайные, отсортированные, все элементы одинаковые.

**Требования.** Генератор случайных чисел создаётся один раз, а не при каждом вызове. Стресс-тест против `std::sort`, в том числе на массивах с большим количеством повторов. В `README.md` — таблица замеров и объяснение: почему на массиве из одинаковых элементов сортировка снова работает за O(n²) и почему случайный выбор опорного элемента здесь не помогает.

**Ожидаемый вид результата** (время зависит от машины):

```text
n = 100000, мс      случайные        отсортированные  одинаковые
быстрая (Ломуто)    7.2              2.8              1553.6
std::sort           5.5              0.7              0.5
```

## ЛР 6 · Бинарный поиск и многофайловый проект

### Базовое задание: lower_bound и upper_bound в модуле

**Условие.** Оформите бинарный поиск как отдельный модуль CMake-проекта: заголовок `include/search.h` с объявлениями и файл `src/search.cpp` с реализацией функций

```cpp
// индекс первого элемента a[i] >= x; a.size(), если такого нет
std::size_t my_lower_bound(const std::vector<long long>& a, long long x);
// индекс первого элемента a[i] > x; a.size(), если такого нет
std::size_t my_upper_bound(const std::vector<long long>& a, long long x);
```

Массив `a` отсортирован по возрастанию. Стандартные `std::lower_bound` и `std::upper_bound` в реализации использовать нельзя (только в тестах).

**Требования.** `CMakeLists.txt` собирает библиотеку, программу и тесты; тесты запускаются командой `ctest --test-dir build`. Тесты doctest покрывают пустой массив, один элемент, искомое меньше всех и больше всех, повторы, а также сравнивают результат со стандартной библиотекой на не менее чем 1000 случайных массивов. Проект собирается с нуля по инструкции из `README.md`.

### Основное задание: количество событий в интервале

**Условие.** Система мониторинга хранит моменты событий — метки времени Unix (число секунд с 1 января 1970 года). Нужно быстро отвечать на запросы «сколько событий произошло в интервале [t₁, t₂]» (границы включаются).

**Входные данные.** Число событий n (1 ≤ n ≤ 10⁶), затем n меток времени в произвольном порядке (целые числа до 10¹²). Затем число запросов q (1 ≤ q ≤ 10⁵) и q строк вида `t1 t2`. Если t₁ > t₂, ответ — 0. Файл с данными генерирует программа `gen_events`.

**Выходные данные.** q строк — ответы на запросы по порядку. При некорректных данных — сообщение в `stderr` с номером запроса и код возврата 1.

**Требования.** Используются функции из базового задания; каждый запрос обрабатывается за O(log n). Полный файл (10⁶ событий, 10⁵ запросов) обрабатывается не дольше 1 секунды. Тесты на граничные интервалы: границы совпадают с метками, интервал между метками, интервал левее и правее всех данных, перепутанные границы.

**Пример.**

Ввод:

```text
5
30 10 20 40 20
4
20 30
21 29
0 100
30 20
```

Вывод:

```text
3
0
5
0
```

### Дополнительное задание: распределение нагрузки

**Условие.** Есть очередь задач с известными объёмами работы. Задачи нужно раздать k исполнителям: каждый получает непрерывный отрезок очереди (порядок задач менять нельзя). Найдите разбиение, при котором максимальная нагрузка на исполнителя минимальна. Можно задействовать и меньше k исполнителей.

**Входные данные.** Число исполнителей k (k ≥ 1), затем до конца ввода — объёмы задач (целые неотрицательные числа, не менее одного, сумма до 10¹⁸).

**Выходные данные.** Строка `Минимальная максимальная нагрузка: L`, затем для каждого задействованного исполнителя строка `Исполнитель i: задачи  (сумма s)`.

**Требования.** Решение — бинарный поиск по ответу: проверка «хватит ли k исполнителей при пределе L» выполняется жадно за O(n), общая сложность O(n log S), где S — сумма объёмов. Тесты doctest на функцию `min_max_group_sum`.

**Примеры.**

Ввод: `2` и задачи `7 2 5 10 8`

```text
Минимальная максимальная нагрузка: 18
Исполнитель 1: 7 2 5  (сумма 14)
Исполнитель 2: 10 8  (сумма 18)
```

Ввод: `3` и задачи `4 8 1 6 3 7 2 5`

```text
Минимальная максимальная нагрузка: 14
Исполнитель 1: 4 8 1  (сумма 13)
Исполнитель 2: 6 3  (сумма 9)
Исполнитель 3: 7 2 5  (сумма 14)
```
